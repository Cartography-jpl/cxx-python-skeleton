Overview

The approach wraps C++ for Python using SWIG, with all generated wrappers for a project compiled into a single combined shared library (_swig_wrap.la, see swig_rules/swig_rules.am). The interesting design problem this solves is C++/Python object lifetime for “directors” — Python subclasses of C++ virtual classes. The chosen model (swig_rules/lib/DirectorNotes.md) is: Python always owns the object; when a director is passed into C++, SWIG hands out a second shared_ptr that uses a custom deleter (PythonRefPtrCleanup, swig_rules/lib/python_ref_ptr_cleanup.h) which decrements the Python refcount instead of freeing the object. This is implemented as a hand-patched fork of SWIG’s own boost_shared_ptr.i, shipped as swig_rules/include/my_shared_ptr.i (still SWIG-version-conditional at lines 57, 80, 89 — #if SWIG_VERSION < 0x040100 — unchanged since the last review), plus supporting pieces for type-preserving downcast (shared_ptr_type_mapper.i, swig_type_mapper_base.h/.cc, swig_type_mapper.h, swig_to_python.h), exception propagation across the Python/C++ boundary (swig_exception.i, python_exception.h), and boost::serialization/pickle support for director objects (director_serialization.i, swig_pickle.i, serialize_function.cc, weak_ptr_serialize_support.cc), now extended with the cross-archive object-identity-tracking layer described above (swig_serialization_context.h/.cc, serialize_shared_ptr.h).

What’s good

  • The director lifetime scheme has real, non-trivial regression tests, not just documentation. python/tests/unit/director_example_test.py exercises: basic director override, reference counting through std::vector<shared_ptr<T>>/std::vector<std::vector<shared_ptr<T>>> of mixed C++/Python-derived objects (asserting exact __del__ counts), pickling and shelve round-tripping, and exception propagation out of a director override. These assert exact counts of destructor calls and exact exception message text, the right level of rigor for lifetime code.
  • The new object-identity-tracking feature was verified, not just implemented. It has: a positive test (test_director_example_object_tracking’s same_object() assertions, for both pickle and shelve/XML, and for both pure-C++ and python-attribute-mediated sharing), a real bug found and fixed during development (infinite recursion from a self-reference during the “capture on first sight” step in _PythonObjectTrackingState.persistent_id, documented with root cause in the tracking plan), and a genuine backward-compatibility check against a file written by pre-tracking-session code from a separate worktree build, not a hand-constructed approximation.
  • The trickiest corner case (weak_ptr to a director) was deliberately captured as a failing test before it was fixed, historically (commits c4dfa95, ebde4c1/8c2c27b, 8c8b959) — good test-driven-fix pattern, though see below re: its current skipped status.
  • The upstream-diff strategy for my_shared_ptr.i is explicit and documented, not just tribal knowledge — swig_rules/README.md tells the next maintainer to diff against SWIG’s boost_shared_ptr.i on upgrade.
  • Clean separation of “reusable rules” from “consumer conventions.” swig_rules/ has no dependency on skeleton-specific code; SWIG_MAPPER_NAMESPACE is a compile-time #define rather than a hardcoded namespace, so the same rules subtree is reused unmodified across different consuming projects.
  • Exception propagation is handled centrally and correctly for the common cases via swig_exception.i’s %exception block and python_exception.h’s PythonException, which captures the original type/value/traceback via PyErr_Fetch rather than a stringified message.
  • The WIP cleanup for the tracking feature was thorough for the code itself. Every class/function named in the tracking-plan doc as “removed” (PicklerWithSerializationSupport, UnpicklerWithSerializationSupport, the python-side cpickle_module/cpickle_dumps/cpickle_loads, all breakpoint() calls) is genuinely gone — verified by grep across the whole tree in this pass, not just trusted from the doc’s own claim.

What’s concerning / bad

  • SHARED_PTR_NO_OWN is an intentional footgun enforced by nothing but a comment. Unchanged from the last review: nothing in the type system or a debug-build assertion stops a future developer from persisting a SHARED_PTR_NO_OWN value into a long-lived shared_ptr (documented segfault risk in both my_shared_ptr.i and DirectorNotes.md), and the only usage sites are the two parameters in lib/director_example.i:44,47.
  • Heavy reliance on #error stub typemaps for “shouldn’t happen” cases, none of which are exercised. Unchanged from the last review — my_shared_ptr.i’s #error bodies for directorout/varin/varout of various shared_ptr shapes are untested by construction since no .i file in this repo triggers them.
  • serialize_function.cc’s file-based entry points remain untested. serialize_write, serialize_read_generic, serialize_read_binary_generic, the .gz filename-sniffing logic, and DirChange’s restore-on-exception behavior have no direct C++ test — confirmed again this pass by grepping lib/*_test.cc for these symbol names (no hits). All existing serialization coverage still goes through the string-based serialize_write_string/serialize_read_string entry points.
  • The single combined _swig_wrap.la module still concentrates build risk, and the my_shared_ptr.i diff-against-upstream strategy is still entirely manual — both unchanged from the last review; see that version of this document (in git history) for the full detail, still applicable verbatim.
  • bindings/python/swig/*_wrap.cc/.h/.py are committed generated SWIG output, with no automated drift check. These files are written directly into srcdir by the swig_rules.am build rules ($(srcdir)/$(swigsrc)/%_wrap.cc: ...) and are listed in EXTRA_DIST, which is a deliberate, legitimate autotools pattern (it lets a source distribution build without SWIG installed on the target machine) — not a bug. But it does mean these ~2000+ lines of generated code are tracked in git alongside their .i sources with nothing enforcing they stay in sync; a .i edit committed without also regenerating and committing the corresponding _wrap.cc would silently ship stale bindings, and there’s no CI (per claude_notes/build_layout_review.md) that would catch this. Given this session’s diff touched several of these generated files (director_example_wrap.cc, serialize_function_wrap.cc, etc. — see git diff --stat master...HEAD), the regeneration discipline is apparently being followed by hand correctly today, but there’s no check forcing that to remain true.

Testing assessment

Has direct test coverage: - Director basic override + func dispatch, lifetime via plain object/vector/vector-of-vector, pickling/ shelve round-trip, exception propagation through a director — python/tests/unit/director_example_test.py - Cross-boundary object-identity dedup (shared object reachable via pure C++, via a director’s python attribute, and via a nested recursive pickle-inside-boost-serialization call) for both pickle and shelve/XML — test_director_example_object_tracking, same file - Director + weak_ptr combined (SHARED_PTR_NO_OWN) — test_director_example_weak_ptr, no longer skipped; confirmed passing. - Backward-compatible reading of pre-tracking-session files — now a permanent, automated regression test (test_director_example_object_tracking_backward_compat) against a real checked-in fixture (unit_test_data/director_example_object_tracking_pre_dedup_v0.xml), not just a one-off manual check. - Non-director weak_ptr serialization, Printable/operator<<-to-__str__ mapping, blitz⇄numpy array lifetime, Python-file-handle-as-iostream mapping — unchanged from the last review, still covered

Does not have direct test coverage: - serialize_function.cc’s file-based entry points and DirChange’s restore-on-exception path — unchanged. - The #error “unimplemented” typemap paths in my_shared_ptr.i — unchanged, untested by construction.

Verdict: the object-identity-tracking feature added this session is unusually well-verified (real regression tests, a genuine backward-compat check against an old build now captured as a permanent fixture test, a documented bug-found-and-fixed narrative) — the engineering rigor observed in the last review’s assessment of director lifetime testing continues to hold. The documentation regression this session’s own cleanup introduced (DirectorNotes.md) and the leftover dead code (swig_type_mapper.h’s cpickle_*) have both been fixed, and the previously-flagged high-risk gap (weak_ptr + director test skipped) turned out to be an unexplained side effect rather than a real known-broken path — it’s un-skipped and passing now. The remaining open items below (serialize_function.cc file-based entry points, the #error stub typemaps, the manual my_shared_ptr.i upstream-diff process) are all lower-risk, longstanding gaps rather than anything introduced or discovered this session.
